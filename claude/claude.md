# Project: Ticketmaster iOS (React)

## Behavior Rules

- Commit to one solution. Do not present multiple options unless explicitly asked.
- No "maybe", "you could", "alternatively", or "it depends" without immediately resolving it.
- Do not add TODO comments. Implement it or don't.
- Do not over-engineer. Match the complexity of the existing codebase.
- No unsolicited refactoring. Fix what's asked, nothing more.
- No explaining what you're about to do. Just do it.

## Code Style

- Functional components only.
- No unnecessary state. Derive from props where possible.
- No nested ternaries. Use early returns.
- Keep components focused. One responsibility per component.
- Name things clearly. No abbreviations.

## Decision Making

- When something is ambiguous, make a reasonable assumption and state it in one line.
- Do not ask clarifying questions mid-task. Make a call.
- Prefer simplicity over cleverness.

## Token Efficiency

- No verbose comments. Code should be self-explanatory.
- No restating the task before starting.
- No summaries after completing a task unless asked.
